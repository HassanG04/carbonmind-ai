# Milestones, Dependencies and Non-Hardware Critical Path
Target: ambitious six-person graduation roadmap; estimates assume ~6 months and regular team availability. Confirm dates/capacity. Dependencies are planned, not completed.

## M0 — Owner setup (week 1)
Repo private with verified protection tier; charters, decision log, factors policy; team onboarding; demo/prod separation. Exit: security & permissions test, README, issues, first tasks.
## M1 — Demonstration prototype (weeks 1–3, parallel)
Antigravity + Codex build static SaaS prototype; owner deploys Vercel if eligible. Exit: synthetic badges, all navigation, mocked interactions, accessibility and build pass.
## M2 — Science + platform minimum (weeks 2–7)
Hassan schema/API/tenancy; Ziad Zeiny calculation fixtures; Ahmed factor/ingestion; Ziad Kishk authz/security. Exit: validated bill kWh -> source-specific emissions with factor trace, tests & login.
## M3 — AI minimum (weeks 5–11)
Karim CV asset inventory + OCR + confirmation; Adham model energy estimation with measured/synthetic-safe fallback; Ahmed forecasting; independent experiments. Exit: models beat documented baseline on holdout OR failure transparently documented, APIs versioned.
## M4 — Gemini + recommendations (weeks 10–15)
Karim Gemini tools/RAG; Ziad Kishk prompt-injection tests; Hassan scenario API; owner reviewed. Exit: role-scoped assistant answers from data with trace; safe fallback on API outage.
## M5 — enterprise consolidation (weeks 14–19)
Scope 1 fuel, Scope 2, basic Scope 3 screening, site comparisons, factor region/version, data uploads, report export, auditing. Exit: demo multi-org isolation tests, reproducible calculation.
## M6 — pilot/defense (weeks 18–24)
University-first and factory sample scenarios, method validation, comparison to baseline, performance/accessibility, cost estimates, research poster and documented limitations. Exit: 15-minute reproducible presentation and evidence archive.

## Critical path
factor/source schema -> activity schema -> pure calculation functions -> actual data validation -> API and tenancy -> evaluation -> optimization -> report. CV, LLM, hardware run alongside and must not block it.

## Fallback levels
If no data access: clear synthetic demo, no claim of measured accuracy. If weak CV: user confirmation/manual inventory. If no meters: label modeled energy, evaluate only on public properly licensed measurements. If hardware fails: remove adapter from demo. If Gemini unavailable: structured deterministic insights. If Vercel collaboration blocked: owner-run deployment or eligible paid team.

## Scope cut order
Keep science accuracy, traceability, tenants, site hierarchy, demo flows, 1 real experiment, assistant. Cut optional smart-home automation, industrial gas imaging, IoT actuators, full Scope 3 automation, LCA, extra specialized gases, microservices complexity.
